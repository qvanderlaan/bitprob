# Hashing

## Current Hash Functions

`bitprob` currently uses two 64-bit hash values.

The first hash is FNV-1a.

The second hash is generated by applying SplitMix64-style mixing to the first hash.

---

## FNV-1a

The initial hash value is:

```text
0xcbf29ce484222325
```

For every input byte:

```text
hash ^= byte
hash *= FNV_prime
```

where:

```text
FNV_prime = 0x100000001b3
```

The implementation operates on 64-bit unsigned integers.

---

## Hash Mixing

The second hash uses a SplitMix64-style mixing function.

The purpose of the mixing step is to transform the first hash value into another well-distributed 64-bit value.

The current implementation is intentionally simple.

It should be treated as a starting point rather than a claim that this is an optimal Bloom-filter hashing strategy.

---

## Double Hashing

Calculating many completely independent hash functions would be expensive.

Instead, `bitprob` uses:

$$
g_i(x) = h_1(x) + i h_2(x)
$$

This generates multiple probe values from two base hashes.

For example:

```text
h1 = ...
h2 = ...

probe 0 = h1
probe 1 = h1 + h2
probe 2 = h1 + 2*h2
probe 3 = h1 + 3*h2
...
```

Each probe is then reduced modulo the filter size.

---

## Why This Matters

Hashing can become a significant part of Bloom-filter lookup cost.

This makes hashing an interesting optimization target.

Future experiments may compare:

* FNV-1a
* SplitMix-based approaches
* faster integer hashes
* different mixing strategies
* independent hash functions
* batch hashing

The goal is to measure the trade-off between hash quality and CPU cost rather than assuming that one strategy is universally optimal.
